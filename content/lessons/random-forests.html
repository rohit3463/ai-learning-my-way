The goal

A single decision tree grown all the way down fits its training data perfectly, but does worse on new data: it memorises noise (Lesson 6). This lesson shows two ways to fix that by combining many trees into one model, called an ensemble:

  • Random forests grow many deep trees independently, each slightly different, and let them vote.
  • Gradient boosting grows many tiny trees one after another, each one correcting the mistakes of those before it.

Why one deep tree is nervous

A deep tree keeps splitting until every leaf is pure, so it draws a little box around every noisy point. Change a handful of training points and the whole tree, and all its boxes, can come out different (Act I).

That sensitivity has a name: high variance. The tree's answers depend a lot on which particular training points it happened to see. In the film's data the deep tree scores 100% on its training points but only 75% on new ones.

Step 1: bootstrap samples

To get many different trees from one dataset, give each tree its own random version of the data. A bootstrap sample draws \(n\) points from the \(n\) training points with replacement: after each draw the point goes back, so it can be drawn again.

Some points get picked twice or more, and some are never picked. The chance that a particular point is missed on one draw is \(1 - \frac{1}{n}\), so the chance it is missed on all \(n\) draws is

\[ \left(1 - \frac{1}{n}\right)^n \approx 0.37 \quad \text{for large } n \]

So each sample leaves out about 37% of the points, called the out-of-bag points (Act II).

A free test set. Because each tree never saw its out-of-bag points, you can test each tree on them. Averaged over the forest, this "out-of-bag accuracy" estimates performance on new data without setting any data aside.

Step 2: random measurements

Bootstrap samples still share most of their points, so the trees can end up alike, especially if one measurement is very strong and every tree splits on it first. Random forests add a second source of variety: at every question, a tree may only consider a random subset of the measurements. With \(m\) measurements, a common choice is about \(\sqrt{m}\) of them per question (Act III).

Step 3: vote

To classify a new point, ask every tree and take the majority. With \(T\) trees:

\[ \text{share for class 1} = \frac{\text{trees answering 1}}{T} \qquad \text{prediction} = \begin{cases} 1 & \text{if the share} \ge 0.5 \\ 0 & \text{otherwise} \end{cases} \]

For numbers instead of classes, average the trees' answers instead of voting. The share of votes is also a handy confidence score: 0.95 means the trees nearly all agree.

Why voting helps

Each tree makes mistakes, but different trees make different mistakes, so the mistakes tend to cancel out in the vote while the real pattern, which every tree sees, adds up.

A simple calculation shows the power of this. Suppose each of 25 trees is right 70% of the time, and their mistakes are completely independent. The majority is wrong only if 13 or more trees are wrong at once, which happens less than 2% of the time. Real trees aren't fully independent, which is exactly why forests work so hard to make them different, but the effect is still large. In the film, 40 trees reach 85% on new points against 75% for one deep tree (Act IV).

Adding more trees never causes overfitting in a forest. Accuracy rises and then levels off, so the only cost of more trees is time.

Gradient boosting

Boosting builds its team the other way round. Instead of many strong, independent trees, it uses many weak trees, often stumps with a single question, and builds them in sequence, each one aimed at what the team so far still gets wrong (Act V).

It is easiest to see with numbers to predict (regression):

  1. Start with the simplest prediction: the average, \(F_0(x) = \bar{y}\).
  2. Measure what is still wrong. The residual of each point is \(r = y - F(x)\).
  3. Fit a small tree \(h\) to predict the residuals from \(x\).
  4. Add a small part of it: \(F(x) \leftarrow F(x) + \eta \times h(x)\).
  5. Repeat from step 2.

The final model is the base plus every tree's small contribution:

\[ F(x) = F_0 + \eta \times h_1(x) + \eta \times h_2(x) + \dots + \eta \times h_M(x) \]

\(\eta\) is the learning rate, just as in gradient descent. Small steps, such as 0.1 or 0.3, with more trees usually work better than big steps with few trees.

Why "gradient"? For squared error \(\frac{1}{2}(y - F)^2\), the slope with respect to the prediction \(F\) is \(-(y - F)\), which is minus the residual. So fitting a tree to the residuals and adding it is a step of gradient descent, taken not on weights but on the predictions themselves. With other losses (log loss for classification, for example) boosting fits trees to the matching gradient instead, which is where the name comes from.

A worked example of boosting

Four points and a learning rate \(\eta = 0.5\):

\(x\)1234
\(y\)1326

Start. \(F_0 = (1 + 3 + 2 + 6) \div 4 = 3\) for every point. The residuals are \(r = y - 3 = (-2, 0, -1, 3)\), and the squared error is \((4 + 0 + 1 + 9) \div 4 = 3.5\).

Fit a stump to the residuals. Try each cut between neighbouring \(x\) values and measure the squared error around each side's average:

CutLeft residuals, meanRight residuals, meanSquared error
\(x \le 1.5\)\(-2\); mean \(-2\)\(0, -1, 3\); mean \(0.67\)\(8.67\)
\(x \le 2.5\)\(-2, 0\); mean \(-1\)\(-1, 3\); mean \(1\)\(10\)
\(x \le 3.5\)\(-2, 0, -1\); mean \(-1\)\(3\); mean \(3\)\(2\)

The best stump is "\(x \le 3.5\)? then \(-1\), otherwise \(3\)".

Add half of it. For \(x = 1, 2, 3\): \(F = 3 + 0.5 \times (-1) = 2.5\). For \(x = 4\): \(F = 3 + 0.5 \times 3 = 4.5\).

The new residuals are \((-1.5, 0.5, -0.5, 1.5)\), and the squared error drops from 3.5 to 1.25 after a single tiny tree. The next stump will focus on what is left, here the split between \(x = 1\) and the rest.

In practice, boosted trees (libraries such as XGBoost, LightGBM and CatBoost) are among the most accurate models for table-shaped data. Random forests are a strong, low-fuss default that is hard to get badly wrong (Act VI).
