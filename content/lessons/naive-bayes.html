The goal

Given a message, decide whether it is spam. Naive Bayes does this by counting words in messages that were already sorted, and then weighing the evidence each word gives.

The notation \(P(\ )\) means "the chance of". A vertical bar reads "given": \(P(\text{money} \mid \text{spam})\) is "the chance of seeing the word money, given that the message is spam".

The data

Seven messages that someone already sorted:

SpamNot spam (ham)
win money nowmeeting at noon
free moneylunch money
win free prizefree lunch at noon
see you now

Spam has 8 words in total and ham has 12. There are 11 different words overall.

Step 1: the prior

Before reading a single word, how common is each class?

\[ P(\text{spam}) = \frac{3}{7} = 0.43 \qquad P(\text{ham}) = \frac{4}{7} = 0.57 \]

This is the prior: our belief before seeing any evidence (Act I).

Step 2: the chance of each word

For each class, count how often each word appears and divide by the total number of words in that class:

\[ P(\text{word} \mid \text{spam}) = \frac{\text{count of the word in spam}}{\text{all spam words}} \]

For example, "money" appears twice among the 8 spam words and once among the 12 ham words:

\[ P(\text{money} \mid \text{spam}) = \frac{2}{8} = 0.25 \qquad P(\text{money} \mid \text{ham}) = \frac{1}{12} = 0.083 \]

So "money" is three times more common in spam. It is a clue pointing toward spam (Act II).

Step 3: Bayes' rule

We know the chance of the words given the class. We want the reverse: the chance of the class given the words. Bayes' rule turns one into the other:

\[ P(\text{spam} \mid \text{message}) = \frac{P(\text{message} \mid \text{spam}) \times P(\text{spam})}{P(\text{message})} \]

The bottom, \(P(\text{message})\), is the same whichever class we are checking. So we can simply compute a score for each class and compare:

\[ \text{score}(\text{spam}) = P(\text{spam}) \times P(\text{message} \mid \text{spam}) \]

and turn the scores into a probability at the end by dividing by their total:

\[ P(\text{spam} \mid \text{message}) = \frac{\text{score(spam)}}{\text{score(spam)} + \text{score(ham)}} \]

Step 4: the naive assumption

What is \(P(\text{message} \mid \text{spam})\) for a whole message? Naive Bayes makes a simplifying assumption: each word appears independently of the others. It ignores word order and which words tend to appear together. That is the "naive" part.

With that assumption the chances simply multiply:

\[ P(\text{free money now} \mid \text{spam}) = P(\text{free} \mid \text{spam}) \times P(\text{money} \mid \text{spam}) \times P(\text{now} \mid \text{spam}) \]

The assumption is rarely exactly true, yet the method works surprisingly well, especially for text (Act IV).

A worked example by hand

Is "free money now" spam? Look up each word:

\[ \text{score(spam)} = \frac{3}{7} \times \frac{2}{8} \times \frac{2}{8} \times \frac{1}{8} = 0.00335 \] \[ \text{score(ham)} = \frac{4}{7} \times \frac{1}{12} \times \frac{1}{12} \times \frac{1}{12} = 0.00033 \] \[ P(\text{spam} \mid \text{free money now}) = \frac{0.00335}{0.00335 + 0.00033} = 0.91 \]

91% spam (Act V).

The zero problem and smoothing

Now try "win lunch". "Lunch" never appears in spam, and "win" never appears in ham:

\[ P(\text{lunch} \mid \text{spam}) = \frac{0}{8} = 0 \qquad P(\text{win} \mid \text{ham}) = \frac{0}{12} = 0 \]

One zero makes the whole product zero, so both scores become 0 and the model has no answer at all. Worse, a single word the model never saw in a class would veto that class completely, however strong the other clues are.

The fix is add-one smoothing (also called Laplace smoothing): pretend every word appeared one extra time in every class.

\[ P(\text{word} \mid \text{class}) = \frac{\text{count} + 1}{\text{words in class} + V} \]

Here \(V\) is the number of different words, 11 in our data. Adding \(V\) to the bottom keeps the chances adding up to 1.

With smoothing, "win lunch" gets

\[ \text{score(spam)} = \frac{3}{7} \times \frac{2 + 1}{8 + 11} \times \frac{0 + 1}{8 + 11} = 0.00356 \qquad \text{score(ham)} = \frac{4}{7} \times \frac{0 + 1}{12 + 11} \times \frac{2 + 1}{12 + 11} = 0.00324 \]

which gives 52% spam: nearly a coin toss, which is honest for such mixed evidence (Act VI). With smoothing, "free money now" comes out at 75% spam rather than 91%. Smoothing makes the model a little less extreme.

Long messages: use logarithms

A long message multiplies hundreds of small numbers, and a computer rounds the result down to exactly 0. The fix is to add logarithms instead of multiplying, because \(\log(a \times b) = \log a + \log b\):

\[ \log \text{score(spam)} = \log P(\text{spam}) + \log P(\text{word}_1 \mid \text{spam}) + \log P(\text{word}_2 \mid \text{spam}) + \dots \]

The class with the larger log score is the same class that has the larger score, so the decision doesn't change.
